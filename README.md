# ИИ-помощник по каталогу ekt.kz

Прототип консультанта для электротехнического магазина. Первая часть проекта даёт страницу помощника, backend-клиент каталога ekt.kz и явный демонстрационный режим. Виджет получает данные только с backend; Basic Auth браузеру не передаётся.

## Архитектура

```text
Браузер: HTML/CSS/JS → FastAPI → поиск в каталоге → ekt.kz Products API
                                      ├→ OpenAI Responses API → ответ по карточкам
                                      └→ demo catalog / локальный fallback
```

FastAPI хранит настройки доступа на сервере, передаёт Basic Auth только запросам каталога, ограничивает время ожидания и преобразует HTTP-ошибки в безопасные сообщения. Нормализатор заполняет известные поля, сохраняя исходную карточку; неизвестные поля остаются пустыми.

## Запуск

Нужны Python 3.11 или новее и pip.

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
python -m uvicorn backend.main:app --reload
```

Откройте <http://127.0.0.1:8000>. Документация backend доступна по адресу <http://127.0.0.1:8000/docs>.

## Настройка каталога

Добавьте учётные данные в локальный `.env`:

| Переменная | Назначение | Значение по умолчанию |
|---|---|---|
| `APP_ENV` | Режим приложения | `development` |
| `EKT_API_BASE_URL` | Адрес API каталога | `https://ekt.kz/api` |
| `EKT_API_USERNAME` | Логин Basic Auth | пусто |
| `EKT_API_PASSWORD` | Пароль Basic Auth | пусто |
| `EKT_API_TIMEOUT_SECONDS` | Тайм-аут запроса | `10` |
| `OPENAI_API_KEY` | Ключ OpenAI API, используется только backend | пусто |
| `OPENAI_MODEL` | Модель OpenAI Responses API | `gpt-6-astra` |
| `OPENAI_TIMEOUT_SECONDS` | Тайм-аут запроса к OpenAI | `30` |

Файл `.env` исключён из Git. Пример содержит только пустые значения; секреты нельзя добавлять в исходный код, клиент или логи.

В live-режиме backend обращается к `GET /products`, к последующим страницам добавляет параметр `page`, а карточку загружает из `GET /products/detail?id={id}`. Точная схема ответа нормализуется адаптером по фактическим полям. Статус на главной странице выполняет реальный запрос каталога и показывает live-режим только после успешного ответа.

Если доступ не настроен, backend явно включает demo mode с одной демонстрационной карточкой. Эти данные не представляют реальные остатки или цены ekt.kz. Ошибки авторизации, тайм-ауты и другие ответы upstream не раскрывают заголовки или секреты.

## Чат и OpenAI API

Backend ищет совпадения по словам и артикулу среди первых страниц каталога и при необходимости получает подробные карточки найденных позиций. Найденные поля передаются модели OpenAI через Responses API вместе с инструкциями отвечать только по каталогу; браузер не получает ключ OpenAI. Запросы выполняются с `store: false`. Модель и ключ задаются через `OPENAI_MODEL` и `OPENAI_API_KEY`.

Если ключ не задан, чат явно показывает локальный резервный режим: ответ составляется из фактически найденных значений, без облачной модели. С ошибкой OpenAI backend отвечает сообщением об ошибке, не подменяя её выдуманным результатом. Для облачных ответов укажите ключ OpenAI API в локальном `.env`; он не включён в `.env.example`.

## API прототипа

- `GET /api/status` — состояние live/demo подключения.
- `GET /api/products?page=1` — страница каталога.
- `GET /api/products/{product_id}` — карточка товара.
- `POST /api/chat` с JSON `{"message":"..."}` — поиск по каталогу и ответ помощника.

Внешний API проверяется на первом запуске с настроенными переменными окружения. В этой среде схема и авторизация API пока не подтверждены; не считать интеграцию live проверенной до такого запуска.

## Текущий объём

Поиск сейчас ограничен первыми тремя страницами API. Подбор аналогов и демонстрационная корзина относятся к следующим частям ТЗ. Реальная корзина ekt.kz не предоставлена среди read-only endpoints.
