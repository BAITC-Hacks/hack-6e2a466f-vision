# ИИ-помощник по каталогу ekt.kz

Прототип консультанта для электротехнического магазина. Четвёртая часть включает диалог с ограниченной историей одной сессии, проверенные ответы OpenAI, поиск аналогов и изолированную демонстрационную корзину. Виджет получает данные только с backend; ключи API браузеру не передаются.

## Архитектура

```text
Браузер: HTML/CSS/JS → FastAPI → Catalog adapter → ekt.kz Products API
                              ├→ OpenAI Python SDK / Responses API → Pydantic → ответ
                              └→ SQLite: история сессии и demo cart adapter
```

FastAPI хранит настройки доступа на сервере, передаёт Basic Auth только запросам каталога, ограничивает время ожидания и преобразует HTTP-ошибки в безопасные сообщения. Нормализатор заполняет известные поля, сохраняя исходную карточку; неизвестные поля остаются пустыми.

## Запуск

Нужны Python 3.11 или новее и pip.

Основные зафиксированные зависимости: FastAPI 0.115.12, HTTPX 0.28.1, Pydantic Settings 2.8.1, Uvicorn 0.34.0 и официальный OpenAI Python SDK 3.19.0. `requirements.lock.txt` фиксирует также транзитивные зависимости.

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.lock.txt
Copy-Item .env.example .env
python -m uvicorn backend.main:app --reload
```

Откройте <http://127.0.0.1:8000>. Документация backend доступна по адресу <http://127.0.0.1:8000/docs>.

## Настройка каталога

Добавьте учётные данные в локальный `.env`:

| Переменная | Назначение | Значение по умолчанию |
|---|---|---|
| `APP_ENV` | Режим приложения | `development` |
| `EKT_API_BASE_URL` | Адрес API каталога | `https://ekt.kz/api` |
| `EKT_API_USERNAME` | Логин Basic Auth | пусто |
| `EKT_API_PASSWORD` | Пароль Basic Auth | пусто |
| `EKT_API_TIMEOUT_SECONDS` | Тайм-аут запроса | `10` |
| `OPENAI_API_KEY` | Ключ OpenAI API, используется только backend | пусто |
| `OPENAI_MODEL` | ID доступной проекту модели OpenAI Responses API | пусто |
| `OPENAI_TIMEOUT_SECONDS` | Тайм-аут запроса к OpenAI | `30` |

Файл `.env` исключён из Git. Пример содержит только пустые значения; секреты нельзя добавлять в исходный код, клиент или логи.

В live-режиме backend обращается к `GET /products`, к последующим страницам добавляет параметр `page`, а карточку загружает из `GET /products/detail?id={id}`. В проверенном live-ответе список содержал 20 товаров и поля `article`, `id`, `name`, `offers`, `price`, `url`; детальная карточка дополнительно содержала `description`, `properties`, `quantity`, `stores`. Категория может находиться в `properties.KATEGORIYA`. Отсутствующие значения не придумываются. Страницы списка кешируются на 60 секунд; перед записью в demo-корзину детальная карточка и остаток читаются заново.

Если доступ не настроен, backend явно включает demo mode с одной демонстрационной карточкой. Эти данные не представляют реальные остатки или цены ekt.kz. При ошибке настроенного каталога UI показывает ошибку; заголовки и секреты не раскрываются.

## Чат и OpenAI API

Backend ищет совпадения по словам и артикулу среди первых страниц каталога и при необходимости получает подробные карточки найденных позиций. Числовой ID можно запросить напрямую. В live AI режиме **вопрос пользователя, до восьми последних реплик этой сессии и только нужные поля найденных товаров отправляются OpenAI API**. Для обработки используется официальный Python SDK и Responses API с `store: false`. Системные инструкции лежат отдельно в `backend/prompt.py`; ответ запрашивается как Structured Output по схеме `AIReply` и дополнительно проверяется через Pydantic. ID товаров и аналогов сверяются с результатами backend. Ключ и модель задаются через `OPENAI_API_KEY` и `OPENAI_MODEL`; оба параметра нужны для live AI режима. Подходящий ID модели должен быть доступен вашему API-проекту.

Документация API: [Responses API](https://developers.openai.com/api/docs/guides/text), [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs). Список доступных моделей можно получить через OpenAI API или посмотреть в настройках своего проекта.

Если ключ или модель не заданы, чат явно показывает `Offline demo — OpenAI API is not configured`: ответ составляется из фактически найденных значений, без облачной модели. Ошибка авторизации, лимита, тайм-аута, отказ модели или невалидного формата отображается как ошибка с предложением повтора; скрытого перехода в offline режим нет. Чат восстанавливает историю после перезагрузки страницы; кнопка сброса удаляет историю и неподтверждённое добавление, сохраняя уже добавленную demo-корзину.

## API прототипа

- `GET /api/status` — состояние live/demo подключения.
- `GET /api/products?page=1` — страница каталога.
- `GET /api/products/{product_id}` — карточка товара.
- `POST /api/chat` с JSON `{"message":"...","session_id":"..."}` — поиск по каталогу, ответы помощника и безопасный сценарий подтверждения корзины.
- `GET /api/cart/{session_id}` — состояние демонстрационной корзины текущей сессии.
- `GET /api/session/{session_id}` — последние реплики и статус ожидающего подтверждения.
- `DELETE /api/session/{session_id}` — новый диалог в той же браузерной сессии.

## Аналоги и демонстрационная корзина

Если у найденной live-позиции остаток равен нулю или наличие не подтверждено, backend загружает детальные карточки похожих по названию кандидатов и сравнивает реальные характеристики. Аналог отображается только при подтверждённом наличии и общем каталожном признаке или категории; объяснение называет совпадения. Служебные маркетинговые поля не используются для технического сравнения. Кандидаты передаются OpenAI для формулировки ответа, а их ID проверяются backend. Без сравнимых полей система сообщает, что данных недостаточно. Demo-позиции не выдаются за товары сайта и в корзину не добавляются.

Покупатель может запросить добавление товара. Backend уточнит количество, затем покажет конкретные товар и количество и попросит отдельное однозначное подтверждение. Только после него backend повторно загружает карточку и остаток, проверяет положительное количество и доступный остаток с учётом уже выбранной позиции. Сессия хранит демонстрационную корзину в SQLite; ссылка «Демо-корзина» ведёт на `/cart`. Повторный ответ на уже обработанное подтверждение не создаёт дубликат.

Доступны только read endpoints каталога. Корзина ekt.kz не меняется: для реального добавления потребуется подтверждённый официальный write API/SDK или согласованная ссылка перехода.

Проверки: `python -m unittest discover -s tests -v`. На четвёртой части прошёл 21 тест: подменённые ответы каталога и OpenAI, схема ответа, тайм-аут и отказ модели, сессии и полный путь от вопроса до корзины. Отдельно проверены live каталог ekt.kz и структурированный ответ OpenAI с доступной проекту моделью; сквозной live запрос по ID товара также сохранил пару реплик в сессии. В браузере проверены ширины 390 и 1280 px: горизонтального переполнения нет, страница корзины на мобильной ширине открывается. Реальные API-вызовы могут расходовать лимиты проекта.

Для ручной проверки откройте главную страницу, спросите артикул или ID товара, затем выберите недоступный товар и посмотрите на кандидатов. Запросите добавление доступного товара и укажите количество: до отдельного ответа «Подтверждаю» `/cart` остаётся пустой. После подтверждения откройте «Демо-корзину». Перезагрузите страницу: история чата и корзина сохраняются в той же браузерной сессии.

## Текущий объём

Поиск сейчас ограничен первыми тремя страницами API. Подбор аналогов опирается на совпадающие поля, которые вернул API; сложное электротехническое сопоставление при неполных характеристиках не выполняется. Корзина является демонстрационной и не записывает заказ в ekt.kz.
